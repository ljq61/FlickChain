# FlickChain《一弹到底》产品需求文档

版本：V0.7 · 日期：2026-10-11 · 状态：连续随机单人与PVP/PVE抢10分已实现，真机与发行验收待完成

本文件把项目聊天「小游戏玩法设计」中的 Web 3D PRD V0.1，以及用户对公共硬币和闯关失败条件的纠正，整理为可执行的产品约定。来源聊天：`6ac608a3-e828-83ec-96ed-47813b5fad49`；配置迁移聊天：`01a120b0-10a0-7790-b802-d8a9f6ed56ba`。工程已有首个可玩版本；本文的参数、性能与内容数量仍有规划项，未经对应层级运行或玩家验证的部分不视为验收通过。

## 1. 产品定位与决策状态

一款手机优先、可在桌面浏览器游玩的 Web 3D 桌面物理小游戏。玩家拉弓弹射当前硬币，准确碰到一枚目标币，就把控制权接到目标币当前位置，连续完成接力；玩家既要碰准，还要为下一杆留下可打的位置。

| 已由用户确认 | 本轮补齐的设计默认值，可经试玩调整 |
|---|---|
| Web 3D 物理玩法；所有硬币公共，无阵营归属 | 产品工作名 FlickChain《一弹到底》；精致微缩桌面、玩具摄影视觉 |
| 1 碰 2 成功：得分、1 消失、从 2 的最终位置继续 | 成功每杆固定 +1；全杆静止后统一计分、删源币和交接 |
| 单人闯关任何失误、掉落、打到多币都会失败 | 单人 CLEAR_ALL；Battle：PVP/PVE先得10分；耗尽补币续局 |
| 单人闯关、人机、本地双人模式 | 单人连续随机轮和本地PVP/PVE |
| 后续石/塑料等弹射物，木/玻璃/冰等桌面；AI 难度升级 | AI 分 Easy / Normal / Hard；连续随机轮难度后续调校 |
| 仅调整方向和力度，硬币位置由物理结果决定 | 超时按模拟步数限制；普通墙/障碍反弹合法；教程和基础音效纳入 MVP |

技术方案采用 TypeScript + Vite + Three.js + Rapier 3D WASM，界面使用 HTML/CSS、Pointer Events 和 Web Audio。它们是本项目的规划选择；物理和性能是否适合目标手机仍需原型验证。架构细节见 `TECHNICAL_ARCHITECTURE.md`，执行顺序见 `TASK_PLAN.md`。

## 2. 体验目标与首发范围

玩家应在短教程后理解「一杆只让当前币直接命中一枚目标，接着从它停下的位置打」。目标币后续推动其它硬币属于物理连锁，不改变本杆唯一直接目标。一次成功的物理接触、停稳和接力转换需清晰可见；失败应明确指出原因，并能迅速重试。历史方案中的单局 2–5 分钟仅作设计预期，不能当作实测时长或上线门槛。

| 交付层级 | 内容与完成边界 |
|---|---|
| 物理原型，阶段 1 | 木桌、标准币、拉弓操作、固定步进、可观察接触/掉落/停稳；不宣称完整游戏 |
| MVP，阶段 1–3 | 完整接力判定；连续随机 CLEAR_ALL 单人；PVP/PVE抢10分；教学、重试、本地进度、基础音效；手机竖屏和桌面布局 |
| 功能完成版，阶段 4–5 | 人机三档难度；随机轮全链体验验证；材质扩展、视觉/音效与兼容优化 |
| 平台交付，阶段 6 | 静态构建、公开部署验证；依当期平台要求准备 CrazyGames 包和媒体，Preview 与实际发布单独验收 |

MVP 范围外：联网对战、账号、排行榜、UGC/关卡编辑器、多材质分区、移动机关、广告、内购、复杂剧情。它们只保留扩展方向，不因角色配置或目录预留而提前开发。

## 3. 核心术语与完整一杆

- **公共币**：任何玩家都能通过规则获得控制权的弹射物，无专属颜色或所有权。
- **当前币 A**：本杆唯一允许发射的币；目标 B 在发射前没有被指定，不是点选锁定目标。
- **接触目标集合**：本杆所有有效、且由源币 A 直接发生的硬币接触中，除 A 外的币 ID 去重集合。A→B 后由 B 撞 C、D 不会扩大该集合；A 直接再撞 C 才算新增目标。
- **一杆**：从输入释放并施加一次冲量开始，到所有可继续参与游戏的动态币满足停稳条件，或达到超时上限为止。
- **停稳**：全场保留硬币有合法稳定支撑，线速度、角速度连续若干固定物理步低于阈值；不只检查 A，空中低速和渲染暂停均不算停稳。
- **掉落**：任意硬币越过明确的离桌/落下判定边界。边界和阈值属于关卡/物理配置，不能按屏幕是否可见判定。
- **犯规**：一杆出现漏击、额外目标、任意币掉落或模拟超时；多项同时发生时保留完整原因记录。

一杆期间不能再次发射、选币或移动硬币。物理继续演算，首次接触只提供反馈，不能立即删 A、计分、切换到 B。待整杆结束统一判定；任何已确定的犯规优先于可能的成功。

成功提交前应确认移除 A 不会破坏其他币的固定支撑；只有安全时才统一删币、加分、交接。若发现异常支撑，保留 A 和分数进入错误恢复，不先删除再判失败。

| 本杆事实 | 结算结果 | 棋盘和操作权 |
|---|---|---|
| 唯一目标 B，无掉落/超时 | 成功，当前玩家 +1 | 结算后删 A；B 保持真实最终位姿成为当前币；同一玩家继续 |
| A 与 B 多次接触，目标集合仍只有 B | 成功，仍仅 +1 | 同上，不按接触次数累计分数 |
| 没有有效硬币接触 | 漏击，+0 | 不删仍在桌上的 A；Challenge 失败；Battle 交给下一玩家 |
| A 的直接接触目标包含 B、C 或更多 | 额外目标犯规，+0 | 不执行成功删 A；停稳后的棋盘保留；模式决定结束/换人 |
| 任意币掉落，无论是否先碰到 B | 掉落犯规，+0 | 安全结算后移除离桌币；其他币保留物理结果 |
| 未停稳且达到模拟步数上限 | TIMEOUT，+0 | 冻结并保留超时步的物理终态；处理已掉落币；不执行成功删 A |

TIMEOUT 冻结后，仅当保留币均有合法稳定支撑才允许对战换人续局。仍有悬空或非法支撑、但尚未确认掉落的币时，保持冻结进入错误恢复，提供重建本局或返回；不能开放下一杆或凭空删除该币。单人仍为失败，不记录通关。

普通桌边墙和障碍反弹合法，不加入硬币目标集合。单纯碰墙后停下属于漏击；碰墙后只碰 B 可以成功。障碍若将币弹出桌面，仍按掉落犯规。有效接触过滤和物理稳定性必须统一实现，渲染特效不能创造规则事件。

犯规一旦确定，立即锁定操作并显示原因。Challenge 可立即呈现失败；Battle 可立即提示失去回合。残余物理仍需安全结算或按 TIMEOUT 冻结，结束后才能激活选币、下一杆、重试或加载新场景。

## 4. 单人连续闯关 Challenge

点击“单人游戏”直接进入第一轮，无选关。每轮仍用 CLEAR_ALL：只有最后一杆合法删源币后剩下一币才进入下一轮；漏击、额外直接目标、掉落或超时都失败，掉落减少至一枚/零枚不算完成。

第一轮自由选起手币，首杆前可换币。最后存活币保留 ID、材质和真实位姿，锁定为下一轮主控币，累计分不重置。旧杯抬起挪走，新增币/杯轻落入场后接着打，无通关确认或“下一关”按钮。暂停冻结模拟和过渡，菜单取消旧局。

| 轮次 | 桌面 | 新增硬币（不含上一轮存活币） | 本轮玻璃杯 |
|---|---|---|---|
| 1 | 木桌 | 4 枚金币 | 0 |
| 2 | 木桌 | 6 枚金币，至少 1 枚新增金币靠边 | 0 |
| 3 | 木桌 | 6 枚金币 | 2，靠中央 |
| 4 | 木桌 | 7 枚，其中 2 枚铁币 | 0 |
| 5 | 光滑大理石 | 7 枚，其中 2 枚铁币 | 0 |
| 6 | 延续大理石 | 7 枚，金币/铁币随机 | 3，靠中央 |
| 7 起 | 木桌/大理石随机 | 5–9 枚，金币/铁币随机 | 3–6，靠中央 |

数量为用户确认的“新增”：第二轮共 7 枚，第四轮共 8 枚。每轮重新随机，杯仅在指定轮出现，不累积。新增币和保留币中心至少相距 16 cm，避让其它币与杯且完整位于桌内；靠边金币中心距桌心 68–73 cm。继承币的第一新目标距其 20–55 cm，并留出无杯/其它币的直达走廊。这避免起手目标全部超距，不保证每个随机残局整轮可解。

- 每次合法接力 +1，整次闯关累计，本地最高即时保存。重新开始从第一轮重新随机、清零本次分，最高分保留。
- 每次完整闯关共 **3 次复活**，换轮不补机会。失败杆安全结算后可复活，保留残局、杯、轮次和分数，重新选一枚币继续，首杆前可换币。
- 若失败杆掉落币，随机补回本杆实际掉落数量的**金币**；不补此前合法消失的源币、不回滚存活币。没有掉落不补，全部掉落则补回后选择。
- 机会用尽再次失败显示最终分数与重新开始/菜单。退出/刷新不保存物理残局或复活余量。
- 旧声音设置兼容，旧已过关字段仅迁移保留，不控制单人入口。随机源可注入测试，运行用随机数，当前不持久化种子/逐杆录制。
- 平台排行榜与广告复活暂缓，不提供广告入口。

## 5. 本地对战 Battle（PVP / PVE）

主界面“本地对战”进入次级界面：PVP为同机两位玩家，PVE为玩家与电脑。双方共享全部硬币；**PVP/PVE先获得10分者获胜**。每局随机选择木桌或低摩擦大理石桌，随机摆放1–5个威士忌杯及共9枚硬币，金币/铁币种类随机。位置经几何校验避开边缘、杯和其它币；不保证任意残局全链可解。

开局先进行比远争先：在本局同材质的空桌、默认相机底侧同一起点，玩家一和玩家二（PVE为你和电脑）各弹一枚金币。方向固定朝桌面远侧，按住蓄力控制力度。完全停稳后记录距起点的位移；有效距离更远者先手。掉落或超时放弃先手；双方均掉落，或两次有效距离差不超过1毫米，重新进行一组比远。结果显示约1.3秒后自动换人或进入正式棋盘。比远不计分，不留下测试币和位姿，每次重开重新比远。

1. 正式开局由获先手者自由选择公共币，首杆发射前可换币。
2. 合法接力+1，删源币A、转控目标B的最终位置；同一玩家继续，B锁定不可换。
3. 漏击、源币直接额外目标、任意币掉落、超时均零分并换手，停稳后保留残局、移除掉落币。下一玩家自由选择任意存活币。
4. 加分后立即检查目标分（两种模式均10分），达标即结束，不进行补币。
5. 未达目标分且桌上仅剩0–1枚：保留比分、当前玩家、桌面、杯和存活币真实位姿。PVP随机补足9枚；PVE每次随机新增8枚金币/铁币，1枚幸存时共9枚、0枚幸存时共8枚。成功末杆保留接力锁定；犯规后仍由下家自由选币。该补币规则由用户确认，解决9枚最多8次接力、可能4:4的情况。
6. 非法支撑/世界异常先进入错误恢复，不能通过补币规避物理问题。

PVE电脑在Worker中使用正式物理与完整结算搜索；可自由选币时评估公共币，接力时只能弹当前B。电脑思考/发射时用户不能选币、蓄力或旋转视角；设置和音量可用。暂停、后台、重开、返回菜单取消旧试算，恢复重新请求。电脑未找到得分解时仍须进行合法输入的真实弹射，允许失误换手，不保证必胜。

## 6. 输入、屏幕与反馈

支持鼠标和触摸的 Pointer Events。游戏使用 3D 透视相机：空白桌面拖动旋转视角，当前相机 forward 投影到桌面后成为唯一弹射方向。起手或换人后点击任意公共硬币，镜头移动到该币；首杆发射前可反复换币，无确认按钮。手指沿发射方向位于当前币正后方，待机平行桌面；按住手指或当前币时逐渐弯曲指节、回收指尖，力度由按住时长控制，松手沿当前视角前方发射。合法命中后只操作刚击中的币。不能把币拖到新位置。指针取消、失焦、超出可控区域等应取消预览，避免误发射；具体取消手势经真机验证后固定。

满蓄力为1.25秒；满档继续按住2秒，取消本次蓄力、恢复待机并播放失败提示，必须松手后重新按住。前几轮左下提示说明此限制，取消不计杆也不改变棋盘。蓄力期间手的屏幕左侧显示竖条，按实际力度从底向上填充，固定渐变绿→黄→红；松手、取消、满档超时、暂停、电脑回合和菜单均隐藏。

当前交互以手指朝向表达发射方向、指节弯曲表达蓄力、硬币发光标识当前币，已移除方向箭头和力度数字；不展示未经生产物理验证的精确多次反弹轨迹。按下命中区和视觉标记需一致，交接后同步移动，避免用户点击已消失的 A。

2026-10-10 表现补充：展示完整卡通握拳的手（掌背、收拢的手指、拇指、腕部与袖口），食指沿金币正后方平放并逐渐弯曲蓄力。高蓄力时加入渐强微抖，取消或松手后恢复；减少动态效果设置关闭抖动。选择当前币后镜头平滑拉近，强调手与当前币，不要求始终显示全桌；起手选币与换人保留较宽视野，空白处仍可旋转查找其它金币。

最新造型使用用户在 Blender 调整骨骼和蒙皮后的动画手 `blender/pointing-hand-rigged.blend`，保留其拳头、食指、拇指和袖口造型。手背朝上、手心朝桌面；食指按按住时长从伸直逐渐向手心弯曲，取消后恢复伸直；其余手指固定收拳。整只手均可触发蓄力，隐藏时不接收手部点击。导出时校准比例、发射朝向与桌面净空。模型自身的袖口开口及分部拓扑按用户源保留，不再要求旧生成模型的封闭单一连通结构。默认圆桌及现有物理、接力与计分规则保持不变。历史造型验收见 [连体手与圆桌验收](validation/2026-10-10-continuous-hand-round-table.md)。

2026-10-11 外观调整：游戏中的手统一缩放为上一版的80%，使用暖肤色、非金属、柔和高光的皮肤材质；指尖与金币距离及整手点击区域随模型同步适配。

2026-10-11 手感与声音调整：最大弹射冲量由0.024提高到0.048 N·s，满蓄力仍为1.25秒。每关入场硬币从桌面上方轻落、短暂弹跳，落稳前锁定选币与发射；落桌和碰撞采用真实硬币录音，滑行使用随桌面运动渐弱的柔和摩擦声。硬币重心仍在桌内时保持平放，真正越界后才允许倾倒，避免临近桌边的异常倾斜与位移。

| 屏幕/状态 | 必须呈现与允许操作 |
|---|---|
| 主菜单 | 路径绘制标题、单人、本地对战及PVP/PVE选择；音量右上 |
| 单人入场 | 直接随机 4 币轻落桌，落稳后选币，无选关 |
| 选择当前币 | 起手或 Battle 换人后点币即时选中；首杆发射前可反复换币，接力后锁定目标币 |
| 可瞄准/拖拽 | 左侧单人计分板显示“x 分 / x 次机会”（机会为剩余复活，非币数），小号“第 x 轮”在面板下；右上音量和设置齿轮，设置用播放/重转箭头/房屋图标表示继续/重开/菜单，保留无障碍名称与悬停提示；右下本地最高；单人不显示多余的轮到你了 |
| 飞行/等待结算 | 禁止发射和选币；当前杆进度及接触反馈，保留场景可读性 |
| 已判失败但未结算 | 立即显示原因；重试/换人激活前等待安全结算，可显示简短等待状态 |
| 换轮/失败 | 自动挪杯补币；失败停稳后复活或重开，显示累计与最高分 |
| 对战结果 | 双方分数、达到目标分的胜者（两种模式均10分）；再来一局、返回菜单 |
| 错误恢复 | WASM/关卡/世界异常或超时非法支撑说明；锁发射，允许重建本局/返回 |

手机以 9:16 竖屏为主要设计面，桌面以 16:9 调整透视镜头距离与 HUD。相机旋转和布局变化不改变桌面尺寸、币位置、规则、力度或物理参数；宽高比变化后仍须看清桌边和可操作硬币。屏幕旋转/窗口缩放不应重开局或误发射。

视觉环境为昏暗酒馆、灯光聚焦桌面；七块木拼板、黑金矿脉抛光石面、厚底威士忌杯与琥珀色酒液均以程序绘制/几何呈现。标题用SVG路径绘制，界面保留暖金与深棕配色。柔和接触阴影、可信尺度、节制高光突出物体与桌边。材质表现服务于辨识和物理预期，不使用刺眼特效遮挡接触。角色区别使用 HUD/文本，不能把公共币画成玩家专属。

背景音乐采用轻柔和弦、低音与稀疏刷鼓的酒馆伴奏，不采用突出萨克斯主奏；音量低于前景击币反馈。音效覆盖拉弓、发射、碰币、碰墙、成功、失败、蓄力超时；音频在用户交互后解锁，提供静音/音量设置。基础可访问要求：关键状态不只依赖颜色或声音；文字和触控控件在目标手机上可读可点；减弱闪烁/震动，支持减少动态效果的偏好。

## 7. 关卡、材质与 AI 递进

连续轮由 CampaignGenerator 生成数据化配置并通过生产几何校验。旧五个固定 JSON 仅留给生产解法回归，不再用于单人入口。原“20 个固定验证关”计划由连续随机轮取代；配方、稳定性、继承、复活、全链体验分别验收。

物理、渲染和点击共用材质：标准金币半径 3.5 cm、质量 12 g、摩擦 0.18；青色铁币半径为金币 1.12 倍、质量 21 g、摩擦 0.30。木桌摩擦 0.18，大理石 0.055。厚底威士忌杯可见高度0.12米，使用固定圆柱碰撞足迹，隐藏底部伸入桌面封闭高速接缝；杯底呈现避开桌面共面，杯反弹合法，不计入币目标。参数为当前调校值，手机手感与难度仍需试玩。

| AI 难度 | 规划行为 | 边界 |
|---|---|---|
| Easy | 较少角度/力度候选，适度操作误差，优先可直达目标 | 误差只影响合法输入，不改物理或规则 |
| Normal | 扩大候选，考虑反弹、掉落风险和 B 的最终位置 | 有限搜索预算，实测响应时间后定值 |
| Hard | 在预算内评估下一杆留位和短链收益 | 不读取玩家隐私，不以作弊冲量/重新摆币提高难度 |

AI 在 Web Worker 中使用生产物理和整杆判定评估候选，不能使用会与真实玩法分歧的简化结果。默认以“合法成功、风险、下一杆位置”排序；超出预算使用已完成搜索的安全候选或合法回退。重试、换局和返回菜单取消旧决策，旧 AI 结果不能发射到新棋盘。

## 9. 关键场景与边界补充

| 场景 | 期望 |
|---|---|
| 首碰 B 后 A/B 长时间运动 | 等整杆结束；不能边动边操控 B，也不提前删 A |
| 先碰 B，稍后 B 掉落或 C 掉落 | 本杆失败 +0；此前显示接触反馈不能被误认成已得分 |
| A 几乎同时直接接触两个目标 | 稳定 ID 去重后判额外目标，不能依回调顺序随机选赢家 |
| B 反弹再次碰 A | 仍一个目标；无其他犯规则合法 |
| 合法命中后 A/B 叠币 | 不因叠放直接重建；移除A后若B需自然落地，保持锁输入直到B稳定，再加分接力 |
| B 撞 C、D，而 A 未直接碰 C、D | 仍只有 B 一个源币目标，合法；C、D 不计入额外目标 |
| 犯规后桌上只剩一枚/全部掉落 | Challenge失败；Battle未到目标分则保留残局，PVP补足9枚、PVE新增8枚 |
| 漏击/多币犯规后 A 未掉落 | 对战下一玩家可选择 A 的真实最终位置或其它公共币；不重摆硬币 |
| 物理永远无法自然停稳 | 到模拟步上限 TIMEOUT；冻结终态，安全支撑局面按模式失败/换人/结束，非法支撑进入错误恢复 |
| 玩家连续快速点按、第二根手指触摸 | 一次只接受有效控制指针，不能多次施加冲量或越权选币 |
| 页面切后台、恢复、尺寸变化 | 安全暂停/取消未释放拖拽；恢复不追赶巨大时间差，不发生误发射 |
| 结算期间按重试/退出，AI 返回旧消息 | 可记录退出意图并安全销毁；新局不继承旧事件、输入或 AI 决策 |
| 初始关卡只有一币、币重叠或超边界 | 正常关卡拒绝；purpose=opening仅允许单枚金币且无杯 |

## 10. 性能、兼容与验收边界

规划目标是主流手机和桌面设备达到流畅的约 60 FPS 渲染、紧凑首次下载、短等待和快速重试。物理固定步进初选 120 Hz，必须在手机原型测量后决定；不得为追求帧率改变同一关卡的世界尺度或隐式变更规则。

首次下载体积、首屏可操作时间、重试耗时、帧耗时、内存峰值和 AI 响应预算都需在阶段 1 基线后定量化。当前没有实测数值，也没有已登记的验收设备，不能写成“兼容通过”。至少登记 iOS Safari、Android Chrome 和桌面主流浏览器的版本、屏幕、机型、构建号及测量场景；能否覆盖低端设备依测量决定。

验收分层记录：规则单测/模拟回放、浏览器鼠标交互、模拟触摸、真实手机触摸/音频/性能、公开部署、CrazyGames Preview、实际平台发布。前一层通过不替代后一层；物理解法在一台设备通过不等于承诺跨设备无条件确定性。

发布阶段再检查平台当期官方 SDK、打包、输入、音频、广告、媒体与审核要求；本文不沿用其他项目的旧限制。早期离线可玩，阶段 6 才接入必要平台功能。未经明确授权不提交审核或执行不可逆平台操作。
