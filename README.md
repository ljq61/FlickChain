# FlickChain《一弹到底》

手机优先的 Web 3D 物理接力游戏。所有硬币公共共享：一杆合法命中唯一目标后获得 1 分，原币在结算后消失，玩家从目标币的最终位置继续弹射。

当前状态（2026-10-11）：单人游戏改为无选关的连续随机轮，最后存活币原位接到下一轮，新币避让后轻落桌；新增玻璃杯、青色重铁币和低摩擦大理石。整次闯关有三次复活，保留残局与累计分，掉落则补回同数量金币；本地记录最高分。本地双人与用户动画手继续可玩。

251项自动化测试、类型检查与构建通过。最新浏览器验证范围见 [开发进度](docs/PROGRESS.md)。随机轮配方、继承/复活、材质与旧固定布局解法分别回归；不承诺所有随机布局完整可解。真机触摸、手机性能、平台排行榜和广告复活仍未接入/验收。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。开局硬币依次轻落桌，落稳后开放选币。空白区域拖动旋转 3D 视角；单人首轮、复活或双人换人后可选择任意公共硬币，首杆发射前可反复切换。合法命中后，必须从刚击中硬币的最终位置继续，不能重新选币。选币后镜头推近当前币，手放在金币正后方，食指待机平行桌面；按住手或当前币蓄力时食指逐渐弯曲、指尖回收，高蓄力时手会轻微抖动，松手沿当前视角前方弹射；力度只由按住时长决定，1.25秒蓄满；满档继续按住2秒会取消蓄力并提示失败，需要松手后重新按住。减少动态效果设置会关闭抖动和入场落桌动画。近景中可通过旋转视角寻找其它硬币。一杆的目标只统计源币直接接触的硬币，双人犯规停稳后换人，换人后重新开放起手选币。

```sh
npm test
npm run validate:levels
npm run build
npm run preview
```

`dist/` 是静态产物；资源采用相对基址。音频由用户操作解锁，存档失败仅提示，仍可游玩。随机内容用配方、几何与生产初稳回归；旧固定布局或物理参数改变须重新生成完整解，步骤见 [关卡测试说明](tests/levels/README.md)。

## 连续闯关配方

| 轮次 | 桌面 | 新增硬币 | 玻璃杯 |
|---|---|---|---|
| 1 | 木 | 4 金币 | 0 |
| 2 | 木 | 6 金币，至少 1 枚新增金币靠边 | 0 |
| 3 | 木 | 6 金币 | 2 |
| 4 | 木 | 7，其中 2 铁币 | 0 |
| 5 | 大理石 | 7，其中 2 铁币 | 0 |
| 6 | 大理石 | 7，金/铁随机 | 3 |
| 7 起 | 木/大理石随机 | 5–9，金/铁随机 | 3–6 |

新增数量不包含上一轮幸存币。新增币与幸存币中心至少相距16 cm，继承币附近留一个20–55 cm内的目标与直达走廊。每轮旧杯抬起挪走后重新摆桌，过渡可暂停。重新开始从随机第一轮开始、分数归零，最高分保留。细则见 [PRD](docs/PRD.md)。

## 模型、物理与音效

手模型以用户调整的 [pointing-hand-rigged.blend](blender/pointing-hand-rigged.blend) 为编辑源，[flick-hand.blend](assets/flick-hand.blend) 为游戏适配副本，[flick-hand.glb](public/models/flick-hand.glb) 为运行资产。导出保留用户骨骼和蒙皮，将 `Index_Curl` 的12–36帧映射为一秒 `FlickCharge`，运行时按蓄力比例采样。袖口开口与原模型拓扑保留，旧封闭连体手属于历史版本。加载失败可用“重建本局”重试。重导方法和资产指纹见 [模型说明](assets/README.md)。

默认圆桌直径1.6米，显示、点击与物理边界一致。`campaign-materials-v4` 最大冲量为0.048 N·s，公共固定步120 Hz，每步执行两个240 Hz Rapier内步，以保持满力度下薄障碍的碰撞。桌边以币心是否越界判断倾倒；开局落桌仅改变呈现，不改变关卡物理初始布局。

硬币撞击、桌面撞击和轻落桌使用真实 CC0 录音；滑行是更柔和的低频合成摩擦层，按桌上移动渐弱。静音、暂停和切关会清理当前声音。作者、来源与剪辑说明见 [音效来源](assets/audio-sources.md)。

酒馆场景采用昏暗背景与桌面聚光，主界面标题为路径绘制 SVG；木桌七块拼板，抛光石面为程序绘制的黑金矿脉。厚底威士忌杯包含酒液与共享半分辨率折射，杯底避开桌面的共面闪烁，碰撞体向桌内延伸以封闭高速撞击缝隙。合法叠币结算会安全移除源币、等待目标币落稳，再正常接力。

首页音量位于右上；游戏中音量下方为设置齿轮，设置内提供重新开始。剩余复活显示在记分板下方，本地最高分在右下。首次铁币/大理石提示解释重量和摩擦差异。背景音乐为轻柔和弦、低音与刷鼓伴奏，无突出萨克斯主奏，离线生成 MP3；生成方法和声音来源见 [音效来源](assets/audio-sources.md)。

[在线游玩](https://ljq61.github.io/FlickChain/)。[发布工作流](.github/workflows/deploy-pages.yml) 在 main 推送后执行 npm ci、完整测试和生产构建，仅将 dist 上传到 Pages；也支持手动重跑。仓库 Pages 来源应设为 GitHub Actions。实际发布结果与提交版本见 [Actions](https://github.com/ljq61/FlickChain/actions/workflows/deploy-pages.yml)。构建使用相对基址，模型、MP3 和 WASM 从游戏子路径加载。

GitHub Pages 是本轮公开静态站点交付；CrazyGames SDK、Preview 与正式平台提交仍未执行。

## 执行顺序

物理手感原型 → 整杆接力规则 → 连续随机单人/本地双人 → Worker AI → 随机轮难度与材质体验打磨 → 性能与平台发行。

PRD 规定产品行为，架构规定实现边界，任务计划规定顺序与完成条件。出现冲突时先更新决策记录并同步三份文档，避免各模块自行选择规则。详细调校参数均为候选，需实际浏览器与设备验证。
